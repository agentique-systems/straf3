# ===========================================================================
# THE THREE LINES, READ OFF THE TABLES ABOVE
# ===========================================================================
#
# TIMES, checkpoint 0 (fork) to checkpoint 1 (rejoin):
#   PURE LOW     5888 ms   (2168 -> 8056)
#   PURE HIGH    7040 ms   (2168 -> 9208)    +1152 ms
#   HYBRID      10560 ms   (2168 -> 12728)   +4672 ms
#
# THE FORK DOES NOT WORK ON THESE NUMBERS, and it is published as a negative
# rather than left as an open question. The harder branch is 1152 ms SLOWER
# than the easier one, so nobody would ever take the leap: it costs a second
# and buys nothing. Three caveats, in the order they are believed:
#   1. Only the HYBRID completed. LOW's and HIGH's times are segments of lines
#      that failed later at the finish, so they are not strictly comparable to
#      the hybrid's segment of a line that finished.
#   2. The searcher delivered 620 ups to the launch lip against a 620 ups
#      worst-approach threshold -- it flew the gate at its exact minimum. The
#      leap sweep above shows best-y climbing 3381 at 600 ups to 3414 at 700,
#      so a line arriving faster lands further and carries more out.
#   3. The HIGH via-chain forces a westward detour the LOW chain does not, so
#      part of the deficit may be the instrument rather than the geometry.
# The map was NOT widened to turn this number around. A trade that exists only
# because its author enlarged one side is a weaker claim than one that survived
# measurement, and this one did not survive.
#
# THE HYBRID IS THE SLOWEST, WHICH IS THE RE-CUT WORKING. Both chicane blocks
# begin at y=3456, downstream of the slot's exit window at y 2944..3392, so
# anything entering the low branch pays its cost in full. The hybrid is
# therefore the low line PLUS the westward climb PLUS the drop. That was a
# construction proof when the map was cut; 10560 against 5888 is the
# measurement agreeing with it.
#
# DELIVERED SPEED AT THE GATES -- ups at the tick of FIRST OVERLAP, committed
# line only, sampled per-tick inside the mover loop:
#   lip_leap     PURE HIGH 620    HYBRID 520    PURE LOW never entered
#   lip_finish   PURE LOW 586     PURE HIGH 817    HYBRID 607
# The best figure delivered to the launch lip by ANY line searched is 620 ups,
# against the 1437 ups an earlier searcher reached by circling the apron for 43
# seconds of simulated time. That is the conditioned answer: a reservoir is not
# a delivery, the clock runs while you farm, and nothing that was trying to go
# fast arrived fast. It is a LOWER bound from a weak searcher, so it does not
# close the question either. The leap's upper bound is UNMEASURED ABOVE THE
# SWEPT RANGE -- the sweep covers 560..700 ups and says nothing about 1437.
#
# ROUTE CLASSIFICATION, and the launch predicate that makes it four-valued.
#
#   LAUNCHED := peak origin z, over the ticks where the hull is inside
#               x -896..-448, y 2944..3392, exceeds 168.
#
# Both halves of r37's condition, in one number. The box begins AT the launch
# lip's face, so a strafe-jump on the lane cannot satisfy it -- that is "beyond
# the lip's face". And 168 is DERIVED, not chosen: the lip surface is z=128, a
# standing hull puts the origin 24 above it at 152, and a jump adds 45.6, so
# 168 sits 16 units above standing height and ~45 below a jump apex. It uses no
# velocity and no duration, so it is reproducible from the shipped binary's
# --trace positions alone -- which matters, because airborne DURATION and
# DISTANCE provably cannot separate a leap from an ordinary strafe-jump.
#
# Measured, and the populations separate on the first attempt:
#   PURE HIGH   GAP peak z 237.7   LAUNCHED     (85.7 units of flight)
#   HYBRID      GAP peak z 152.1   NOT launched (exactly standing height: it
#                                  walked off the lip without jumping)
#   PURE LOW    GAP never entered
# 85.6 units of separation against a 16-unit margin.
#
# The four categories:
#   LOW only                        the sweep was run
#   HIGH + FARSIDE                  the leap was flown and cleared
#   HIGH + LOW + LAUNCHED           fell short -- the failure the slot exists
#                                   to permit
#   HIGH + LOW + NOT LAUNCHED       the DESCENT EXPLOIT: climbed the ramp,
#                                   declined the leap, dropped through and
#                                   crossed. This is what the HYBRID run below
#                                   is, and it faced nothing.
#   NEITHER, on a run that finished  a bypass finding by definition
#
# TWO LIMITS ON THIS COLUMN, stated so it is not over-read later.
#   - LOW-only is NOT evidence of route choice. The low line is what a runner
#     reaches by doing nothing, so entering it proves no deliberation.
#   - Box entry is a PROXY. "Entered HIGH" means "was inside this volume", not
#     "flew the leap"; that is what the LAUNCHED predicate is for.
#   - These regions are DISJOINT CLASSIFICATION BOXES. They are not evidence of
#     solid separation between the branches, which lives in the compiled hulls
#     and is shown by `cargo run -p straf3-map --bin mapdump`. Cleave's branches
#     are demonstrably CONNECTED space across the slot -- the lateral survey
#     above is the proof -- so offering this classification for that purpose
#     would be a category error.
#

# results/cleave-hybrid.txt, 1976 commands. Its command stream replays through
# the shipped binary:
#
#   ./target/release/straf3 --replay probes/course-lab/results/cleave-hybrid.txt \
#       --map assets/maps/cleave.map
#
#     map        29 hulls, 4 triggers, 348 triangles, collision digest 0xd2d7d01e8f9d03ef
#     run        13968 ms  (start 1800 ms, finish 15768 ms)
#     origin     33.307919 5608.835938 168.125076
#     checksum   0xfaeb5a87ed0e773a
#
# course-lab reported 13968 ms and 0xfaeb5a87ed0e773a. They agree bit for bit,
# and the digest line confirms the stream was replayed against the map it was
# made on -- the check the tree requires BEFORE checksums are compared.
#
# AND IT IS THE DESCENT EXPLOIT. The first line anything has driven end to end
# on this map is the one the map was re-cut to make worst. Its GAP peak z of
# 152.1 says it never launched. So it is a valid COMPLETION and it is not a run
# that engaged the fork, and it must never be reported as the latter.
#
# THE LAUNCHED PREDICATE IS CONTESTED, AND THE OBJECTION IS SOUND
# ---------------------------------------------------------------
# Peak-origin-z above 168 separates JUMPED from WALKED. It does not separate a
# committed LEAP from an ordinary strafe-jump, and the failure direction is
# PERMISSIVE, which is the dangerous one.
#
# The arithmetic, from the frozen constants (profile.rs: gravity 800,
# jump_velocity 270, hull_mins.z -24). Apex is 270^2/1600 = 45.5625. Solving
# 400t^2 - 270t + 16 < 0 gives t in (0.0656, 0.6094), so an ordinary hop is
# above 168 for 0.5437 s of its 0.675 s flight -- 80.6%. At 600 ups that is 326
# units of horizontal travel while still above the threshold. The launch box is
# 448 deep with its near face at the lip, so a runner hopping along the lane and
# simply continuing off the end enters the box while ~330 units short of
# dropping back through 168, and would score LAUNCHED without having leapt.
# A leap and a hop are the same ballistic arc from the same jump_velocity; they
# differ in initiation point and horizontal speed, and peak z reads neither.
#
# WHAT THE PREDICATE DID SAY ON THE ONE RUN THAT EXISTS. cleave-hybrid.txt
# measured GAP peak z = 152.1 -- exactly standing height on a z=128 lip, so it
# scored NOT LAUNCHED, which is the correct classification for that run: it
# walked off. The predicate happened to be right here because the hybrid never
# jumped at all, not because it can tell a decline from a commitment.
#
# THEREFORE, AND THIS IS THE CLAIM NOT BEING MADE: cleave-hybrid.txt is NOT
# offered as satisfying r37, NOT recorded as a fell-short outcome, and NOT
# offered as evidence that anything engaged the fork. Whether any run has
# engaged cleave's fork is UNRESOLVED. The run is offered for exactly one
# thing -- that the course is completable and its command stream reproduces
# through the shipped binary.
#
# The constructive direction, recorded rather than acted on because inventing a
# threshold under time pressure is how a fitted constant gets published: a
# committed leap is aimed ACROSS the slot and a decline is aimed DOWN into it,
# so the discriminating quantity is horizontal -- speed at the tick the hull
# last leaves the lip face, or airborne horizontal distance from that face
# before first ground contact, compared against what the lane's own hops
# deliver. Both are readable from --trace. No number is proposed here.
#
# ONE MORE LIMIT ON THE GAUGE BOXES. lip_leap and lip_finish are z 96..300. A
# runner arriving ABOVE z=300 at that y registers no overlap and the gauge
# reports nothing, which is indistinguishable from "did not go there". So a
# gauge reporting no entry may NOT be read as "the runner did not take that
# line" unless the maximum z at that gate's y is separately shown to be below
# the ceiling. The three lines here are safe by inspection -- their GAP and
# HIGH peaks are 237.7 at most -- but the general reading is unsafe, and the
# runs most likely to arrive high are the fast ones a bypass audit is looking
# for. Tunnelling is not a concern: both boxes are 32 deep against a 30-deep
# hull, a 62-unit window, about 5 samples at 1437 ups.
